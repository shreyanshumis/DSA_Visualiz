Why is 5 ^ 3 equal to 6?

3 = 0011

    Bitwise cheatsheet
    Quick reference for pseudocode · signed 32-bit integers
    

    ^ is XOR, not exponentiation. Work one bit at a time. Bit positions start at 0 on the right. Examples below show short positive numbers with leading zeros; negative numbers use 32-bit two’s complement.
    

    

    1 · Read a binary number
    Position:  3  2  1  0
Value:     8  4  2  1
Bits:      1  1  0  1
13 = 8 + 4 + 1 = 1101
    Each place is worth twice the place to its right. Add the place values where the bit is 1.
    

    2 · Truth table: one pair of bits
    ABA & BA | BA ^ B
    00000
    01011
    10011
    11110
    &: both · |: either · ^: different
    

    3 · AND, OR and XOR side by side
      5 = 0101     5 = 0101     5 = 0101
  3 = 0011     3 = 0011     3 = 0011
  &   ----     |   ----     ^   ----
      0001         0111         0110
         1            7            6
    AND keeps shared 1s. OR combines 1s. XOR removes shared 1s and keeps differences.
    

    4 · Shifts and complement
    5 << 1  = 10   0101 → 1010
5 >> 1  =  2   0101 → 0010
~5      = -6   rule: ~n = -n - 1
-5 >> 1 = -3   signed shift keeps the sign
    For non-negative numbers, right shift by k is floor(n / 2ᵏ). Left shift acts like multiplication by 2ᵏ only when the signed 32-bit result does not overflow. ~ flips all 32 bits, not just the few bits printed above.
    

    5 · Shortcuts worth remembering
    x ^ x = 0       x ^ 0 = x
x & x = x       x & 0 = 0
x | x = x       x | 0 = x
(x ^ y) ^ y = x
x & ~x = 0      x | ~x = -1
    XOR can be regrouped and reordered: equal values cancel in pairs. For example, 7 ^ 4 ^ 7 = 4.
    

    6 · Common bit tricks
    TaskExpressionExample
    Odd?(n & 1) == 15 & 1 = 1
    Test bit k(n & (1 << k)) != 05, k=2 → true
    Set bit kn | (1 << k)5, k=1 → 7
    Clear bit kn & ~(1 << k)7, k=1 → 5
    Toggle bit kn ^ (1 << k)5, k=2 → 1
    Remove lowest 1n & (n - 1)12 → 8
    Power of two?n > 0 AND (n & (n - 1)) == 08 → true
    Use non-negative n and bit positions 0–30 for these simple signed-integer examples. Bit 31 is the sign bit. Count set bits by repeatedly clearing the lowest 1 until n becomes 0.
    

    7 · A quick dry run
    a ← 5        // 0101
b ← 3        // 0011
c ← a ^ b    // 0110 = 6
c ← c << 1   // 1100 = 12
PRINT c & 7  // 1100 & 0111 = 0100 = 4
    Write down each updated value immediately. Later statements use the new value, not the original one.
    

    8 · Common exam traps
    • Bitwise vs logical: 2 & 1 = 0, but “2 != 0 AND 1 != 0” is true. AND/OR combine conditions; &/| combine bits.
    • Parentheses first: (5 + 2) ^ 3 = 4, while 5 + (2 ^ 3) = 6. Precedence rules vary by language; use the question’s rules.
    • Complement is signed: ~5 is -6, not 10. (~5) & 15 is 10 because the mask keeps only four bits.
    • Zero is not a power of two: always include n > 0 in the test.
    • Shifts have limits: overflow can change the sign. In this app, shift counts use their lowest 5 bits; use 0–31 and don’t assume shifting by 32 clears a number.
    • Loop bounds: these questions use inclusive FOR bounds. Trace every iteration and every PRINT in order.
